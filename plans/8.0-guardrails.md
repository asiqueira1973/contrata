## Como se prova
`./scripts/test-guardrails.sh` monta o JSON que o Claude Code entrega ao hook (Write com `file_path` e `content`) e confere o código de saída: 2 bloqueia, 0 libera. `guard-migrations` e `guard-tests` rodam num repositório git temporário com uma migration commitada e o arquivo `.claude/fix-mode`.

| Hook | Escrita que deveria ser bloqueada (e foi) | Casos que devem passar |
|---|---|---|
| guard-secrets | `SUPABASE_SERVICE_ROLE_KEY` em página pública; `GOOGLE_CLIENT_SECRET`, `S3_*`, `NEXT_PUBLIC_*_KEY`; `"use client"` importando `@/server/` | service role em `src/server/`; `SESSION_SECRET` em `src/app/convite/`; componente comum |
| guard-audit | `.from('rs_eventos').update/delete/insert`, inclusive quebrado em linhas | `rpc('rs_fn_registra_evento')`; `select` na trilha |
| guard-decisoes | `rs_fn_confirma_decisao` na API v1; `closeApplication` no MCP; `rs_fn_encerra_candidatura` na API pública; `rs_fn_muda_acesso` e `rs_fn_convida_membro`; chamada quebrada em linhas | `proposeDecision` na API v1; `confirmDecision` na rota do painel; `rs_fn_encerra_candidatura` no domínio |
| guard-copy | "algoritmo", "pontuação", "score", "match", "eliminatória", "eliminada", "fit cultural" | "Underscored"; copy comum; `s.match(` fora da copy |
| guard-migrations | editar migration versionada | migration nova |
| guard-tests | editar `.test.ts` e pgTAP com `fix-mode` | teste sem `fix-mode`; código com `fix-mode` |
| remind-advisors | escrever migration dispara o lembrete (código 2) | arquivo comum |

Resultado: `42 de 42 casos ok`, código 0, na primeira execução.

## Divergências do spec
Nenhuma. O ponto de atenção era `\bscore\b` e `\bmatch\b` no `guard-copy`: o `grep -E` do macOS aceita `\b`, e o caso "Underscored" confirma que não há falso positivo.

## Fora do alcance deste teste
Os hooks só rodam numa sessão do Claude Code aberta **em `~/contrata`**. Esta sessão foi aberta em outro projeto, então o teste chamou os scripts diretamente. A prova de integração (o Claude Code tentar um Write proibido e ser barrado) fica para a primeira sessão em `~/contrata`: rode `./scripts/test-guardrails.sh` e peça uma edição proibida uma vez.

`npm run verify` e o subagente `verifier` dependem do projeto Next do 8.1; o 8.0 não tem código a verificar além dos hooks.
